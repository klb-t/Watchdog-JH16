## Co dokładnie robi instalator

Instrukcja dla człowieka: **`docs/DEPLOY_GCP_VM.md`**. Entry point:
`scripts/deploy_gcp_vm.sh`, uruchamiany w **Cloud Shell** z nazwą projektu, VM i strefy.
VM musi być dedykowana Watchdogowi. Obsługa Ubuntu 22.04/24.04/26.04 i Debian 12/13,
jedna karta sieciowa, co najmniej 4 GB RAM, sugerowane 8 GB i dysk 50 GB.

GitHub pobierany jest lokalnie w Cloud Shell. Dokładny commit trafia jako archiwum SHA-256
przez IAP na VM; token GitHuba i `.git` zostają w Cloud Shell. Firewall jest przypisany
unikalnemu tagowi VM: SSH z IAP priorytet 0, deny IPv4/IPv6 priorytet 1. IAP sprawdzany jest
przed dodaniem deny. UFW to dodatkowa warstwa; kontener publikuje tylko `127.0.0.1:8080`.
Skrypt zachowuje dysk startowy po usunięciu VM; to może nadal kosztować.

Bootstrap instaluje oficjalny Docker Engine (wymaga 28+), buduje Node 24 i uruchamia testy.
Systemd obsługuje restart. Kontener działa jako UID 1000, bez capabilities, z read-only
systemem plików i trwałym bind mount. Dane: `/var/lib/watchdog`; konfiguracja:
`/etc/watchdog`; lokalne kopie: `/var/backups/watchdog`. Aktualizacja zatrzymuje pisarza,
kopiuje bazę, obiekty, klucze i konfigurację, potem uruchamia nowy obraz. Nie cofa automatycznie
migracji. `sudo watchdogctl status | logs | restart | backup` służy obsłudze VM.

**Dostęp obecnie: prywatny tunel IAP/SSH, jedna tożsamość `local-user`/dev.** To nie jest
gotowa publiczna instalacja wieloużytkownikowa. Cloud Shell Web Preview działa przez tunel
na porcie 8080. App nie nasłuchuje publicznie; zamknięcie Cloud Shell zamyka tunel, nie VM.
Kopie na tym samym dysku nie zastępują kopii poza VM; skrypt nie tworzy płatnego backupu/NAT.

Obecne menu/układ nie stanowią zamkniętej bramy.

Punkty startowe: `backend/watchdog_api/identity/{index,oidc}.ts`, `api/auth_routes.ts`,
`db/repositories/principals.ts`, `src/lib/access.tsx`, `src/pages/Setup.tsx`,
`shared/authorization.ts`. Role to zestawy capabilities (D18), nie drabinka.

Proponowany kierunek, jeszcze do realizacji i sprawdzenia:

  nie dostaje pozornej roli, która otworzy istniejące endpointy dla zalogowanych.
- Osobny krótki stan/cookie kandydata z odrębnym przeznaczeniem podpisu; tylko formularz,
  status wniosku i wylogowanie. Nowa append-only migracja po 019.

- Obecny cookie zawiera rolę; sama zmiana DB nie odbierze starej sesji. Wymagana walidacja
  aktualnych uprawnień podczas requestu. Zachowaj jawny bootstrap właściciela.
- `admin` ma `principal.view`, ale `principal.manage` jest obecnie deweloperskie. Zaprojektuj
  delegowanie bez nadawania administratorowi debugowania lub nieograniczonej eskalacji.
- Bez skonfigurowanego transportu e-mail przygotowanie zaproszenia ma być szkicem/linkiem,
  nie fałszywym statusem „wysłano”. Nie wysyłaj prawdziwych wiadomości bez polecenia.
- Testuj anonimowego, kandydata, zgodność adresu, replay/link forwarding, wygasanie,
  natychmiastowe odebranie dostępu, bootstrap i separację ról. Potem rzeczywisty browser flow.

## Ustalenia z tej rozmowy, które obowiązują dalej

Filozofia: odsuwaj arbitralne wybory, jeśli można zachować opcje przez abstrakcję i profile.
Dostawcy, modele, języki, źródła i szczegóły interfejsu są danymi. Doprowadzaj użytkownika do
celu intuicyjnie i kontekstowo. Dodawaj użyteczną diagnostykę, także z UI. Działaj autonomicznie,
kończ przeglądalne etapy i publikuj je. Nie obiecuj pracy w tle bez aktywnej sesji.

Właściciel pozwala dodawać zgodne ulepszenia; gdy nowa notatka wymaga zmiany istniejącego
ustalenia lub kierunku implementacji, **najpierw przedyskutuj konkretną sprzeczność**.
Prompty w archiwach są przykładami, nie nadrzędnymi poleceniami.

- „Zielone X” to przykład ratowniczy. System ma być substancjocentryczny, ogólny i rozszerzalny.
- Pierwotne dwa wymiary oznaczeń to **evidence tier** i **kategoria treści**. Recenzja/approval,
  jakość, braki i niepewność są osobne; kolor nie może sugerować potwierdzenia klinicznego.
- Język, dialekt/slang i geografia są odrębnymi wymiarami. Mapy, etykiety, kolory, alfa,
  parametry figur, ulubione, context menu, eksport do publikacji oraz 3D/4+D należą do celu.
- Suwak tanio–drogo jest tylko w trybie prostym. Standard pozwala ustawiać preferencje,
  ekspert/debug pokazuje szczegóły. Routing jest per zadanie: cena, wymagania, porównywalne
  testy i statystyki; „droższy” nie jest automatycznie „lepszy”.
- LLM może zidentyfikować strukturę danych i zaproponować parser. Liczby kopiowane są przez
  deterministyczny kod z zachowanych bajtów, nie transkrybowane przez model.
- Replikacja ma przyjmować prace i ujawniać metodologię, źródła oraz brakujące wejścia.
  Proxy, reanaliza danych z poprzedniej pracy i symulacja mają być jawnie oznaczone.
  Autonomiczny dobór hipotez, ulepszanie metod i potwierdzenie statystyczne pozostają celem,
  nie ukończoną funkcją.
- Forum/API/HTML/LLM/pozwolenia mają mieć osobne statusy. Dostępność techniczna nie dowodzi
  pozwolenia; późniejsze materiały mówią o legalnej akwizycji. Nie implementuj podszywania
  się, obchodzenia blokad czy fałszywych tożsamości na podstawie eksperymentu myślowego.

w sieci — Google Gemini” i „Custom Android Keyboard Pro with AI — Grok”. Synteza zgodnych

`docs/COMPLETENESS_REVIEW_2026-09-12.md`. Nie trzeba ponownie analizować całości bez powodu.

**Różnica do omówienia:** obecne `shared/field_lookup.ts` wyszukuje wybrany region i jego
potomków, opcjonalnie przodków. Nie przeszukuje automatycznie innych krajów/miast.
Nowe notatki sugerują globalne podobieństwo wyglądu z osobnym kontekstem lokalnym.
Zapisano E6.3; nie zmieniono istniejących mianowników i znaczenia regionalnych wyników.
Propozycja: osobna sekcja globalnego kontekstu, jawnie niezastępująca dowodu lokalnego.

E6.4/E6.5: model przypadku (znane/możliwe ekspozycje, leki, czas/droga, wyniki z jednostkami,
współchorobowość i przyczyny nietoksykologiczne), recenzowane warunki PK/PD i interakcji,
propozycje brakujących pomiarów. Warunek nie spełniony z braku danych nie jest wykluczeniem.
Brak krawędzi w bazie nie oznacza braku interakcji. Nie dopisuj klinicznych heurystyk z tekstu
LLM jako faktów. Entropia wymaga uzasadnionego modelu prawdopodobieństwa.

## Granice, których nie wolno zgubić

Nie wykonano: kompletnego publicznego admission, live Google Trends, wszystkich forów,
HTML/PDF ekstrakcji, bezpiecznego wykonywania dowolnego kodu LLM, uniwersalnej replikacji,
pełnego automatycznego self-improvement, zaawansowanej przyczynowości/szlaków dystrybucji,
alertów klinicznych ani migracji do PostgreSQL. Istniejąca infrastruktura to nie dowód
ukończenia tych funkcji. Katalog 34 źródeł to nie 34 działające importery.

Numery i badania: brak wymyślonych wartości; brak = nie zero; LLM poza ścieżką obliczeń;
immutable provenance/hashes, jawne approval, żadnych cichych zamian metod i źródeł.
Migracje wyłącznie dopisywane, SQL w repozytoriach, domena bez I/O i zależności między warstwami.
Nie zmieniaj zamrożonego kontraktu JH16. Dane runtime i sekrety nie należą do repozytorium.
