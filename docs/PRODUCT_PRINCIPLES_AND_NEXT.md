# Product direction — maintainer clarifications, 2026-09-11

Start from the user's goal and context. A responder, analyst or scientist should see the
next useful action, its prerequisites and the shortest available path. Preserve options:
providers, task policies, presentation, sources and method variants are data profiles;
introduce an abstraction when multiple implementations are useful. Missing capabilities
become inspectable extension work, not plausible placeholder output.

The maintainer authorizes continued implementation, testing and milestone pushes. These
requirements extend the earlier narrow-slice scope; provenance and the locked JH16
comparator still apply. A mode switch must not grant permissions. Language is not geography.

## Next connected capabilities and acceptance criteria

- Personal profiles for at least a dozen established LLM endpoints, shared protocol
  adapters, current model discovery and separately attributed price data. A key for one
  provider must never be tried against another. Unsupported features remain explicit.
- Cost slider only in simple mode. Automatic task routing must consider applicable
  benchmark evidence and measured operational history as well as price. Unknown quality
  stays unknown. Separate extraction planning, trip-report interpretation, method
  proposal, query expansion and narrative tasks; public bulk downloads use code.
- Arbitrary paper intake: preserve submitted text/identifier, extract source-anchored
  methodology, inputs, assumptions and missing requirements; queue candidate attempts.
  Every substituted source/construct or reused prior dataset changes the attempt's
  meaning explicitly. Reusing original data is reanalysis; synthetic expert views
  cannot become observations of actual experts.
- Extension workshop: LLM-proposed adapters and parsers carry fixtures, contracts,
  validation results and immutable versions before activation. Extraction copies data
  deterministically from archived bytes; a model proposes locations or code, never
  transcribes empirical values into the numeric pipeline. No arbitrary generated code
  runs with the application's credentials or database access.
- Contextual goal navigation, prerequisite repair actions and resumable work. Favourites
  should preserve useful workflows as well as chart styles, scoped to the owner.
- Repeated paper scanning should feed bounded hypothesis proposals and eligible research
  attempts. Separate discovery from confirmation, freeze comparison families, retain
  negative outcomes and avoid tuning on confirmation data. Autonomous profile changes
  must be testable and reversible, with the prior version retained.

These are implementation requirements, not a claim that arbitrary scientific work or
every possible external API is already supported. Completion is recorded in ASTRA_PROGRESS.
